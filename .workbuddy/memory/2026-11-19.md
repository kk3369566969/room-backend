## 会议室后端重构 + 迁移 MyBatis-Plus

- 技术栈：Spring Boot 3.3.5 / Java 17，移除 `spring-boot-starter-data-jpa`，改用 `mybatis-plus-spring-boot3-starter:3.5.9` + `mybatis-plus-jsqlparser`（3.5.9 起分页器拆包）。
- 包结构：`controller / service / mapper / entity / dto(request|response) / enums / config / security / client / common`，删除旧 `domain`、`web` 包。
- 主键仍是 `BINARY(16)`，通过 `config/mybatis/UuidBinaryTypeHandler` 做 UUID↔bytes 互转；实体 `@TableId(type = IdType.INPUT)` + 字段初始值 `UUID.randomUUID()`。
- 审计字段由 `config/AuditFieldHandler`（MetaObjectHandler）填充 createdAt/updatedAt/submittedAt。
- 唯一手写 SQL：`resources/mapper/ReservationMapper.xml` 的 `selectOverlappingForUpdate`（重叠查询 + FOR UPDATE）。
- Controller 不再直接返回实体，统一走 `dto/response` + 静态 `of(...)` 工厂；REST 契约（字段、状态码、错误码）保持不变。
- 坑1：`@RequestScope` 的 AuthContext 不能在 Filter 里用（Filter 早于 DispatcherServlet）。改为 AuthFilter 写 Servlet 请求属性，AuthContext 通过 RequestContextHolder 读取。
- 坑2：`submittedAt` 只有 `@TableField(fill=INSERT)` 但 handler 未实现填充 → 插入报 `Column 'submitted_at' cannot be null`。
- 验证：`scripts/smoke_test_refactor.py` 覆盖 39 项断言全通过；另手工验证 PENDING→EXPIRED、CONFIRMED→COMPLETED 惰性结算。

## 日志体系（@Slf4j）

- `common/log/TraceIdFilter`（HIGHEST_PRECEDENCE+1）：每请求生成 8 位 traceId 写 MDC、回写 `X-Trace-Id` 响应头，结束时按状态码分级输出 `[访问]` 日志（5xx ERROR / 4xx WARN / 2xx INFO）+ 耗时。
- `AuthFilter` 解析登录态后把学工号（无档案则 externalId 前 6 位）写入 MDC 的 `user`，之后业务日志自动带人。
- `common/log/Logs`：`maskPhone`（138****0001）、`abbrev`；令牌与 wx code 从不打印。
- 日志 pattern（application.yml）：`%d %highlight(%-5level) [%X{traceId:-no-trace}] [%X{user:-anon}] %logger{36} - %msg%n`；`logging.charset.file: UTF-8`（不设会按 Windows 默认 GBK 写文件，中文乱码且无法 grep）。
- 落点：控制台 + `logs/room-booking.log`（20MB 滚动 / 保留 7 天）。
- 业务标记：`[登录] [登出] [身份提交] [身份审核] [预约创建] [预约取消] [预约审批] [状态结算] [停用创建] [停用解除] [房间更新] [微信登录] [业务异常] [参数校验失败] [访问]`。
- 共 41 处日志点，9 个类加 `@Slf4j`；冒烟 39 项仍全绿。

## 开发模式免登录（dev-mode）

- 起因：接口都要求「已登录 + 身份 APPROVED」，本地没登录全部 401。
- `AuthProperties` 增加 `devMode`（默认 true）与 `devDefaultUser`（默认 `manager-demo`），配置项 `app.auth.dev-mode` / `app.auth.dev-default-user`，环境变量 `AUTH_DEV_MODE` / `AUTH_DEV_USER`。
- `AuthFilter` 优先级：Bearer 令牌 → （devMode 时）`X-User-Id` → （devMode 时）默认账号兜底；devMode 关闭时两者都不生效（顺带修掉「生产可用 X-User-Id 伪造身份」的隐患）。
- `AuthFilter.@PostConstruct initDevMode()`：激活 `prod`/`production` profile 时强制关闭并打 ERROR；开启时打 WARN。
- 冒烟脚本第 1 组用例改为 `X-User-Id: no-such-user` 验证 401 分支（原来用「不带请求头」，会被默认账号兜底成 200）。
- 注意：开发模式下提交身份资料要用「不存在的 X-User-Id」（如 `new-user-1`），用默认 manager-demo 会 409；`/auth/logout` 仍 401（无会话）。
- 本机 8080 常被 IDEA 启动的实例占用，验证时用 `SERVER_PORT=8081` 另起，不要 kill 用户的 IDE 进程。

## 修正：无效凭证不再绕过开发模式

- 现象：Apifox/Postman 里仍报 401，而 curl 不带任何头是 200。原因是 filter 里「Bearer 优先」是硬分支：只要带了 `Authorization: Bearer xxx`（哪怕是过期令牌）就不会走 dev 兜底；`X-User-Id: {{userId}}` 这类未解析的 Apifox 环境变量会原样发出，查不到用户 → 401。
- 改法（`AuthFilter`）：`resolveByBearer` 改为返回 boolean；失败（头缺失 / 令牌为空 / 会话无效或过期）时，devMode 下继续走 `X-User-Id` → 默认账号。`{{...}}`/`}}` 形态的占位符视为「没传」并打 WARN。
- `X-User-Id` 指向未建档账号时仍绑定 externalId（保留「首次提交身份资料」的能力），但打 WARN 列出演示账号。
- `AuthContext`：新增 `ATTR_DEV_MODE`（AuthFilter 写入）；401 的 message 在开发模式下自解释——未建档账号会写明「账号 [x] 尚未建立用户档案，请先 POST /identity/reviews…」，完全无身份会写「可带 X-User-Id（student-demo / teacher-demo / manager-demo），或删掉 Authorization 后裸访问」。
- 验证（8081 → 后 8080）：无头 / 空 Bearer / 无效 Bearer / `{{userId}}` 占位符 全部 200；未建档账号 401 且 message 带指引；39 项冒烟全绿。
- 8080 已由 jar 进程接管（用户确认）。若之后要在 IDEA 里跑，需先停掉这个 java 进程，否则端口冲突。
